Description

In this assignment, you’ll create your own personal website using Quarto. By the end of this assignment, you’ll have a website that you developed using data science tools. You’ll also see how Quarto pages fit together like a puzzle to create a finished website.

Why make a website at all? Having a website is a great way of developing a digital portfolio of your skills and interests. Read Elizabeth Pearson’s “4 Reasons Having a Personal Website Will Help Your Career” for more.

How does making a website using Quarto actually work? In class, we use Quarto markdown documents to write code with text, then render the document into the format we want (usually .pdf or .docx). One major benefit to using Quarto + Rprojects is that 1) Quarto renders to .html and 2) Quarto can render a bunch of Qmd files in a single project to create a website.

Why make a website using Quarto? It’s a great way of demonstrating your skills to the data science community to show that you have some competency in knowing how Quarto documents work together.

Workflow

Part 1. Plan your website

List the “pages” you want to include on your website with section headers.

Plan your website in a word doc or in Google docs. Do not code this.

For your project page, you could format using blog posts. You can enhance these with citations, figures, etc. to fill them out. Alternatively, you could use the blog post format to highlight classes you’ve taken to show you’ve developed skills in whatever those classes are about (for example, literary criticism, GIS, visual art). Note: you can have multiple pages in “blog” format - see Sam Csik’s personal website where the “talks & workshops”, “courses”, “projects”, and “posts” pages are all “blogs”.

Throughout your website, you could also have photo galleries to share any visual media you might have - illustration, photography, etc.

Part 2. Make your website.

a. Create a new repository on GitHub and clone it to your computer.

On GitHub, create a new repository called your-github-username.github.io. For example, An’s GitHub username is an-bui, so her repository name would be called an-bui.github.io.

Make sure you add a README when you are creating your repository.

Clone that repository to your computer.

b. Make R/Rstudio understand that this project is a website.

In the terminal, type:

quarto create-project --type website
Expand this to see what your Terminal window should look like

c. Make some adjustments

These steps adjust some of the default rendering in Quarto.

  1. Still in the terminal, type:

    touch .nojekyll

    This will disable some of the processing that Quarto will do for html files by default.

Expand this to see what your Terminal window should look like

  1. Open the _quarto.yml file.

    At the top of this file, you should see a section that starts with project:.

    Make sure that all the rendered versions of .qmd files in your website go into a folder called docs by editing the _quarto.yml:

    project:
  type: website
  output-dir: docs

# ~~ leave the other parts of the file as they are for now ~~
Expand this to see what your file should look like

d. Quit out of RStudio.

This step is to force the RStudio interface to provide a new tab in the top right of the window.

After you’ve quit out of RStudio, open it again with your website .Rproj file.

e. Render your website

After every change you make to any files in your website, you should render it.

In the top right corner, you should see a tab labelled Build.

Expand this to see what your RStudio window should look like

Click the blue right arrow labelled Render Website.

You should see your website preview pop up in the Viewer pane (in the bottom right).

Expand this to see what your RStudio window should look like

f. Stage, commit, and push your changes to the remote.

Do all of this in the Git tab.

g. Deploy your website using GitHub.

In your remote repo, navigate to Settings > Pages.

Be sure that Branch is set to main and the folder is set to \docs.

Expand this to see what your GitHub window should look like

Then, navigate back to the main page of your repo.

h. Find your deployment.

On the right hand side of the page, you should see a tab called Deployment.

Click on that link to find the URL for your website.

Note: you may see something along the lines of “Failed to deploy…”. Don’t worry about it! Wait for a few seconds, then refresh the page. You should see a new deployment pop up.

Expand this to see what your GitHub window should look like

Click on your website url. Rejoice!

Expand this to see what your website should look like
